# Ledger-Reoptimization

[English](README.md)

这是 [Ledger](https://github.com/QuiltServerTools/Ledger) 的**性能优化分支**。
Ledger 是一个运行在服务端的方块与操作记录模组（Fabric）。

> **Ledger 本身的功劳全部属于原作者。** 本分支不是要取代或超越它，只是为了修复几个
> 性能与易用性上的问题而存在。具体改了什么，下面写得很清楚。

---

## 为什么要做这个分支

Ledger 本身很好用，但日常使用中有两件事让人头疼：

1. **一次记录大量改动时很慢**，短时间内发生很多事（大规模建造、爆炸、批量编辑）时，
   数据库会跟不上。
2. **在游戏里查不到指令是干什么的。** 单独输入 `/ledger` 只会得到一句语法错误，
   也**没有 help 指令**——唯一的参考是浏览器里的 wiki。

所以我们优化了慢的部分，并补上了缺失的游戏内帮助。

## 与原版相比改了什么（用大白话说）

下面每个数字都是在真实的 Minecraft 26.3 服务器上、与上游 1.3.25 **跑同样的负载**
测出来的，不是估算。

### 更快

| | 结果 |
|---|---|
| 记录一批改动 | 大约**快 25%** 完成 |
| 记录时的数据库吞吐 | 最高约**每秒多记 33%** |
| 查询"这块地方谁改过" | 大约**快 64%** |
| 把撤销掉的东西放回去 | 略快 |

### 更省空间

| | 结果 |
|---|---|
| 每条方块改动记录 | 大约**小 5%** |
| 每条带容器/生物数据的记录 | 大约**小 15%** |

省空间这件事是**越到后面越重要**：繁忙服务器的记录库会长到几个 GB，
这个差别决定了它最后是还能管得住、还是彻底失控。

### 新增

- **`/ledger help`** —— 游戏内的指令说明。直接输入会列出全部指令；
  输入 `/ledger help <指令>` 会显示那一条指令的用途、用法、简写和所需权限。
  **单独输入 `/ledger` 现在也会显示这份列表**，不再是语法错误。
- **`/ledger compact`** —— 把较早的记录转换成更紧凑的格式，并回收腾出来的磁盘空间。
  数据库用了很久的话很有用。
- **`/ledger exportlegacy`** —— 见下面「想换回官方版本」。

### 没有改变的

- **回滚（rollback）速度与原版一样。** 我们**如实说明**，而不是暗示这里有提升：
  本分支做的是存储与记录这一侧的工作，而回滚的瓶颈在于往世界里写方块，
  这部分我们没有改动。
- **记录什么、怎么玩，完全不变。** 同样的事件、同样的指令、同样的配置格式。

## 兼容性

- **Minecraft 26.3**（含 26.3.1 等补丁版本），Fabric，**仅服务端**。
  **客户端不需要安装任何东西。**
- **旧数据库可以直接用。** 用旧版本建好的数据库，首次启动时会自动升级——
  不需要改配置、不需要手动操作，升级过程中原有的记录始终可正常读取。
- 服务端需要 `fabric-api` 和 `fabric-language-kotlin`，这一点与原版要求相同。

### 想换回官方版本

本分支会把部分内容以更紧凑的形式存储，未经修改的官方版本读不了这些内容。
如果将来想换回官方版本，先执行**一次**：

```
/ledger exportlegacy
```

它会把那些内容完整还原成文字，之后官方版本就能正常读取你的数据库了。
这条命令在你需要之前不产生任何代价——这也是为什么采用这种方式，
而不是让每条记录都一直变大。

## 安装

1. 从 [Releases](../../releases/latest) 下载 jar。
2. 放进服务端的 `mods` 目录，**先移除其他版本的 Ledger**。
3. 重启服务端。

其余步骤与上游的安装说明相同。

## 关于版本说明里的数据

每个版本说明都会写明改了什么，以及（在有意义的时候）支撑这些改动的实测数据。
**只有在"交替配对"测出来的数字才会公布**——先跑 A 再跑 B 的测法，
在这台机器吞吐会随时间漂移的情况下，会得出看起来有意义、实际不成立的结论。
**我们宁可写"没有变化"，也不发布一个好看但不真实的数字。**

## 一句话总结

让 Ledger **记录更快、占盘更小**，并补上它一直缺的指令说明——除此之外没有动别的。
